tbis vs Photon

Both are Jellyfin desktop clients built by the same author, both play video through mpv. Photon (Tauri + React + TypeScript) is the older, more mature, cross-platform client. tbis (native Rust + GPUI) is a newer, deliberately smaller macOS-only rewrite.

Screens below are live screenshots where the running app could be captured; Photon's Login/Details/Player/PiP frames are pulled from its own repo (docs/screenshots/) since those exact states weren't reachable live without touching a real server session or your live browser tabs.

Worth porting

Ranked by effort to bring into tbis's actual stack (native Rust/GPUI, mpv-only, macOS-first). "Port" here mostly means reusing the lesson, not the code — React/Tauri and GPUI/native share almost no literal syntax.

low effort

Screen wake-lock during playback

tbis already links objc2/objc2-foundation for macOS. Wrap IOPMAssertionCreateWithName (or just shell out to caffeinate -s for the mpv process's lifetime) around active playback in player.rs. Small, contained, fixes a real annoyance (screen sleeping mid-movie).

low effort

Per-item audio/subtitle memory

tbis's config.rs already has a working save/load pattern (atomic tmp+rename, 0600 perms). Add a track_memory: HashMap<String, TrackChoice> field next to movies_sort/series_sort — same shape as Photon's trackMemory.ts, same file, no new mechanism needed.

medium effort

OS Now Playing + media keys

macOS-native via MPNowPlayingInfoCenter/MPRemoteCommandCenter (objc2-app-kit or a small manual bridge). Genuinely useful — media-key and lock-screen/AirPods scrubbing for a video app is a real gap, and tbis's mpv-under-GPUI setup already tracks all the state (position, title, play/pause) this needs.

medium effort

Auto-update mechanism

Not tauri-plugin-updater itself (Tauri-only), but the pattern is worth copying: one silent background check per launch, download, "Restart to update" gate before install+relaunch. For tbis: GitHub Releases + a small Rust updater (e.g. self_update crate) replacing the running .app bundle.

medium effort

Keyboard shortcuts cheat-sheet

Cheap polish, real discoverability win. tbis already has a modal/overlay pattern (Autoplay card, search) to build this on top of — just needs a static list of its own bound actions.

high effort, real payoff

Cross-platform mpv surface (Linux/Windows)

Not portable code (Photon's Linux path composites mpv into a GtkGLArea under WebKitGTK; Windows scales a child HWND to physical pixels for HiDPI) — but Photon's changelog is a ready-made bug list for whoever builds tbis's mpv/linux.rs and mpv/windows.rs for real: Wayland vs X11 split, "consume frames while hidden," HiDPI child-window scaling. Worth reading before writing those modules from scratch.

low effort

PATH lookup for spawned mpv

Already ported — tbis's pip.rs checks /opt/homebrew/bin/mpv and /usr/local/bin/mpv before falling back to bare mpv, mirroring the exact bug Photon hit and fixed (Dock/Finder launches don't inherit shell PATH). No action needed, just confirms the lesson already landed.

Not worth porting

Either infra-specific to Tauri, or conflicts with tbis's own stated minimalism (its CONTEXT.md defines a small, closed vocabulary of screens on purpose).

The updater plugin itself, the settings-page framework, the Zustand stores

tauri-plugin-updater, React Router pages, CSS modules, base-ui dialogs — none of it runs in a webview-less GPUI app. Only the behavior is reusable, never the implementation.

Full Settings surface (Appearance / Playback / Server / Advanced / Stats)

tbis's domain doc never mentions a Settings screen — it's not an oversight, it's the design. Grafting Photon's five settings pages on would directly contradict "the app always merges every Library, so the user never picks one" style minimalism running through the rest of tbis. Port individual toggles only if a specific one is requested, not the whole section.

Server-negotiated DeviceProfile / transcoding fallback

Photon's deviceProfile.ts is genuinely excellent (hard-won HDR-range and subtitle-profile bug fixes), but it exists to solve a problem tbis's architecture already sidesteps: tbis always requests the static original file and lets mpv decode whatever it is, no negotiation round-trip. Porting the negotiation logic would add real complexity to remove a failure mode tbis doesn't currently have.

Quick Connect login

Real Jellyfin feature, genuinely missing from tbis — but it's a scope decision (add a login mode), not a technical port. Worth a deliberate "do we want this" call, not a drive-by port.

Watch-time stats store

Nice, but purely additive local analytics with no other feature depending on it. Low priority unless specifically requested — doesn't fix a gap, just adds a screen.
